# 任务 11：变量与作用域设计

## 背景与目标

任务 11 将当前最小名字绑定扩展为严格的声明、赋值、块级作用域、多重赋值、list 解包和 `global` 语义。以 `docs/tasks/11-variables-scope.md` 为需求基线，交付独立的 `MsScopeCtx` 模块，并保持任务 09/10 的顶层全局行为及现有函数、控制流和容器能力无回归。

当前 `ms_compiler.c` 已有局部槽、块回绕、函数上下文和隐藏临时槽实现，但其声明与赋值路径只支持单目标且不检查声明状态。本次抽取并扩展现有机制，不重写编译器，也不提前实现任务 14 的 upvalue 或任务 26 的通用迭代协议。

## 方案选择

采用“独立作用域上下文 + 现有代码生成路径扩展”。`MsScopeCtx` 负责名字和槽位状态，`ms_compiler.c` 负责诊断与指令生成，`ms_vm.c` 负责 list 解包运行时语义。

不直接继续扩张编译器私有结构，因为任务明确要求独立模块；也不重构整个函数或控制流编译器，因为那不是完成本任务所必需的改动。

## 模块与状态

新增 `src/compiler/ms_scope.h` 和 `src/compiler/ms_scope.c`，并将源文件加入 `CMakeLists.txt`。头文件使用 `MSLANG_SRC_COMPILER_MS_SCOPE_H_`，包含自身所需的标准头和 `MsResult` 定义。

`MsScopeCtx` 每个函数编译上下文持有一份，包含：

- 固定容量的 256 项局部表，每项保存借用的 `MsString*`、声明深度和预留给任务 14 的 `isCaptured`。
- 当前局部数、局部槽高水位、当前块深度及固定容量的块入口表。
- 按需倍增的 `globalNames` 数组；这是该模块唯一拥有的动态分配，销毁时释放。
- `isModule`，区分模块顶层声明集合与函数内强制全局集合。

块入口同时记录 `localBase` 和当前表达式语句使用的隐藏丢弃槽。离开块时回绕存活局部数，兄弟块因此复用槽位；`localMax` 不回绕，最终写入 `MsProto.localCount`。命名局部和隐藏临时槽共用同一分配上限，超限或块深度超限由编译器报 E306。

作用域模块提供初始化/销毁、块进入/离开、局部声明和隐藏槽分配、最内层优先解析、当前深度查询、全局名标记和查询。字符串指针均为借用，字符串内容比较使用 `msStringEquals`。

## 编译器接入与名字解析

`MsFuncCtx` 内嵌 `MsScopeCtx`，在 push/pop/abort 的所有路径配对初始化和销毁。现有参数、函数名、逻辑表达式临时值及表达式丢弃槽统一使用该上下文，避免两套槽位计数。

保留现有 `msCompilerInit` 以支持仅持有 heap 的 C 单元测试，增加内部 `msCompilerSetState` 和 `MsCompiler.state`；`msEvalFile` 在编译前传入当前 `MsState`。 store 解析只有在需要判断非局部名字是否已存在时查询 `msStateGetGlobal`，无状态的 C 编译测试不假装存在内建。

读取名字保持“当前局部 → 强制全局/外层局部桩 → 全局”的既定行为：当前局部优先；函数中已 `global` 的名字绕过外层局部；外层局部仍报任务 14 的 E310；其余读取生成 `LOAD_GLOBAL`，未定义名留到运行时报错。

写入名字时，当前局部或已声明/已注册全局可接受，未声明名字报 E301。函数内 `global` 名直接生成全局指令。模块深度 0 的 `:=` 记录到 `globalNames` 并生成 `STORE_GLOBAL`；块内 `:=` 生成局部槽和 `STORE_LOCAL`。

## 声明、赋值与 global

声明和赋值共享目标处理，但分别执行以下规则：

- RHS 总是先于新声明生成，保证 `x := x` 读取外层或全局旧值。
- 多 RHS 先按从左到右生成全部表达式。无星号时 RHS 个数必须等于目标数；有星号时至少要有 `n - 1` 个 RHS，否则报 E303。
- 单 RHS 且多目标时生成 `MS_OP_UNPACK`，再写回各目标。
- `:=` 在 RHS 之后按目标从左到右登记新槽或新全局；同深度已存在的名字作为普通赋值目标。全部目标都已存在时报 E302。登记完成后按从右到左发射存储指令，使栈自然排空并保证交换赋值正确。
- 星号目标只作为解包目标使用，其声明与存储作用于星号内的标识符。
- `=` 不创建名字，逐目标执行严格 store 解析。下标和属性目标给出阶段性编译错误，不实现任务 15/16 的写回。
- 复合赋值保持单目标的 load-op-store 生成。当前 parser 在构造单目标 AST 前已拒绝多目标或多 RHS，将该诊断从 E205 改为 E305；不为了非法语法扩大 AST。
- 模块顶层 `global` 只记名、不发射指令，与顶层 `:=` 共存不冲突。模块块内或函数内若名字已是存活局部则报 E304。
- 当前代码已经支持基础函数，因此函数内 `global` 在本任务直接生效：之后的读写直达全局，已标记名字再作为 `:=` 目标报 E304。

`del` 仍不实现；裸标识符、下标和属性删除均由既有不支持语句路径编译失败。

## UNPACK 指令

在 `ms_opcode.h` 定义 `MS_UNPACK_NO_STAR` 为 `0xFFFF`。`MS_OP_UNPACK` 使用 ABC 格式：`A` 是目标总数，`Bx` 是星号目标的零起始下标或 `MS_UNPACK_NO_STAR`。目标数超过 255 时编译失败。

编译器在 RHS 已占一项的基础上发射 `UNPACK`，栈深变化为 `n - 1`，并沿用统一高水位核算。多 RHS 下的星号形式已由任务 10 提供 `BUILD_LIST`，可按任务文档直接展开：星号前的目标和尾部目标逐项对应，中段 RHS 由 `BUILD_LIST` 收集；不发射 `UNPACK`。

VM 分支要求源对象为 list：

- 非 list 通过 `msRaiseTypeError` 报 `cannot unpack non-list '<type>'`。
- 无星号要求长度等于 `n`；有星号要求长度至少为 `n - 1`。长度错误通过 `msRaiseValueError` 报告期望和实际个数。
- 按目标顺序产生值；星号位置创建新 list 并收集中段元素，其余位置从源 list 头部或尾部取值。
- 在任何可能分配的操作前保持源对象位于帧栈中，失败经既有位置包装和协程恢复路径返回，成功后才消费源栈项。
- 栈容量和下标在访问前检查，运行时错误退出码为 1。
